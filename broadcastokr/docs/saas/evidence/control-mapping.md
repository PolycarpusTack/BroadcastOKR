# Control Mapping — Client Edition Security Bar (2026-08-31, updated 2026-11-26)

Maps the pre-first-client minimum bar (`2026-08-31-security-design-review.md` §7) to
implemented controls and their proof. Regenerate the `.txt` evidence with
`bash scripts/generate-evidence.sh`.

| # | Bar item | Control | Proof |
|---|---|---|---|
| 1 | SSO + MFA + server sessions; no shared/baked browser credentials | OIDC Authorization Code + PKCE (`bridge/routes/auth.cjs`); opaque server-side sessions, HttpOnly/SameSite cookies, 8h sliding / 7d absolute (`bridge/sessions.cjs`); cloud builds carry no `VITE_BRIDGE_API_KEY` path — sessions only; cloud instances refuse to start without OIDC config (fail-closed, `server.cjs`) | `oidc-flow.txt`; fail-closed test in the same suite |
| 2 | Server-enforced RBAC, proven by UI-bypass tests | Declarative policy table over all route families (`bridge/middleware/rbac.cjs`): member = check-ins/kanban; manager = create/edit; owner-only = deletes, clients, credentials, config, raw SQL, backup, migration, role changes (incl. self) | `rbac-bypass-battery.txt` |
| 3 | Persistent, append-only audit with server-derived actors | `activity_log` (migration 002, 90-day retention); server-side emission for sign-in/out, role changes, connection/config changes, sharing-flag flips (`bridge/audit.cjs`); cloud modes ignore client actor claims | audit assertions inside `rbac-bypass-battery.txt` |
| 4 | Agent hardening bundle | **Implemented (v1)**: one-time 15-min enrolment tokens → per-agent revocable bearer tokens (hashed); outbound-only pushes; the agent's SQL lives solely in its local operator-owned config (no SQL or commands over the network); `{krId, value:number, timestamp}` is all that can serialize; per-agent random 256-bit data key generated at enrolment (`agent-data-key`, kept across re-enrolment; `AGENT_DATA_KEY` from a keystore/secret manager overrides it) and `encrypt-password` (stdin) so configs hold no plaintext; identity, key and config owner-only on every OS (0600 / Windows ACL, `utils/secretFile.cjs`); opt-in SPKI pinning of the instance with two slots, revoke keeps the audit row, owner purge, 30-day sweep (ADR 2026-10-22); read-only envelope underneath (row 9). **Residuals:** cert-bound mTLS (later, ADR 2026-10-22); read-only DB account is an install-guide requirement per client (`docs/operations.md` Security Notes) | `agent-lifecycle.txt`, `agent-hardening.txt` |
| 5 | Opt-in egress enforcement, push-only cockpit channel | **Implemented**: allowlist projector is the single builder of outbound data (FF-4 sentinel-proven, shipped before the channel); push-only — the cockpit holds no credentials against instances; per-tenant write-only tokens (hashed, owner-minted, re-mintable); strict cockpit-side schema validation rejects unknown fields and non-numeric values, audited. v1 shares krId/value/target/direction/timestamp only. **Open contract question:** delete-on-revoke of previously shared rows (logged for legal) | `sharing-channel.txt` |
| 6 | TLS/HSTS, encryption at rest, EU residency | Deployment-level: instances sit behind the platform's TLS termination (`trust proxy` set; cookies `Secure` on https base URLs); at-rest and region are provisioning/platform choices per instance | provisioning env (`BRIDGE_BASE_URL` https) |
| 7 | Isolation evidence: scripted provisioning + cross-tenant tests | Dedicated instance per client (`scripts/provision-instance.mjs`, refuses overwrite, 0600 env, seeded pinned client); single-tenant enforcement server-side (2nd client / last-client-delete → 403); client bundles physically exclude fleet surfaces | `provisioning.txt`, `tenant-isolation.txt`, `bundle-exclusion.txt` |
| 8 | Backups/DR, IR/vuln process | Automated online snapshots (startup + daily, keep 14) per instance; snapshot-consistent download owner-only; the bridge closes its database on SIGTERM/SIGINT/IPC stop and the restore runbook removes `-wal`/`-shm` (a left-over WAL silently undid restores — R2 drill 2026-11-26, r1-findings #42); upgrade 0.9.2 → main and rollback drilled locally. IR/vuln process = Mediagenix partnership scope (**transfer to be confirmed in writing** — open). **Open:** off-machine backups, key recovery and timings on staging | `data-integrity.txt`, `scripts/local-rig/r2-upgrade-restore-drill.mjs` |
| 9 | Customer data cannot be modified through the query runner | One-statement SELECT scanner (`bridge/whatson/sqlEnvelope.cjs`) + database-enforced read-only transaction on the same connection (PG `BEGIN READ ONLY`, Oracle `SET TRANSACTION READ ONLY`), DB-side timeouts, advisory locks released before pool return (ADR-A2). Real-driver acceptance on PostgreSQL 17 and Oracle 19c with write-capable disposable accounts (r1-findings #38/#39). **Known limits, guarded by grants:** Oracle autonomous-transaction functions, NEXTVAL, DBMS_LOCK; the reader account rule is in `docs/operations.md` | `sql-envelope.txt` |
| 10 | Licence terms enforced server-side | Tier + caps from the provisioned env (`bridge/editions.cjs`); gated routes and live/shared-KR writes refused (`403 entitlement`), caps on clients/users/agents (`403 entitlement_cap`); usage report for invoicing (FF-8) | `entitlements.txt` |
| 11 | Mediagenix operator access is narrow and audited | Operator token is a separate principal accepted only in client mode, on a closed allow-list of calls (`OPERATOR_ALLOW`), audited as `Mediagenix operator`; the cockpit forwards a fixed set of calls, no generic proxy; agent purge is not reachable over it (R6-1) | `operator-channel.txt` |
| 12 | Supply chain and release provenance | Releases are built only by CI from a `v*` tag (`release.yml`: installers, GHCR images, agent bundle); runtime lockfile installed with `npm ci --omit=dev` (F3); dependency audit per evidence run | `release-runs.txt`, `dependency-audit.txt` |
