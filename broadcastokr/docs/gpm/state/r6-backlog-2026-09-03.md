### ST0 ADR — the operator channel

- **Decision:** an **operator channel from the cockpit to each tenant instance.**
  A client instance is provisioned with `BRIDGE_OPERATOR_TOKEN`; the cockpit stores
  each tenant's `instance_url` and that token (encrypted with the credential
  cipher) on its `cockpit_tenants` row (migration 008, additive). Tenant bridges
  accept the token in `X-Operator-Token` as an audited **operator principal**
  (`req.user = { role: 'operator', operator: true }`) that may call only a written
  allowlist — connections CRUD, test-connection, channels, the pinned client's
  GET/PUT, and the agents ops routes. Everything else answers 403. The cockpit
  exposes `/api/cockpit/tenants/:clientId/…` (owner-only) that forward to the tenant.
- **Alternatives rejected:** binding on the tenant instance as owner (S, but the
  customer's owner holds the same role and would see and change the binding —
  reverses the 2026-09-03 decision that connection binding is Mediagenix's);
  binding at provisioning only (a database change after go-live becomes a
  re-provision).
- **Trust boundary, stated:** the channel is cloud-to-cloud inside Mediagenix's
  platform, over TLS, with a per-instance secret. It never reaches a customer
  site: agents remain outbound-only and the cloud still sends them no SQL
  (Tier 2 assumptions 1–2 untouched). The token is not a session: no cookie, no
  role escalation path, constant-time compare, and an `Invalid operator token`
  401 for anything that presents the header and does not match.
- **Agents panel:** one `AgentsPanel` component, mounted on the client edition's
  Settings page (its own `/api/agents`) and inside the cockpit's tenant modal
  (through the channel) — as the readiness plan's wording and the pickup block both
  asked.
